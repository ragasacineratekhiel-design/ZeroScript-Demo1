### 2.2 Grammar gaps found while defending the parser

Every row is a script that the 4.7.0-dev analyser **rejected**, and `main.js` blocks
`execute_luau` on a rejection — so each one threw away correct model-written code.

| # | Construct | Was | Now |
|---|---|---|---|
| 2.2a | `local a, b, c = 1, 2, 3` | "expected a local name but found number 2" | name-list then value-list |
| 2.2b | `a, b = b, a` and `t.x, t.y = 1, 2` | "expected an expression but found ','" | `,` continues a target list only when an assignment follows |
| 2.2c | `local x: number?` / `function f(): T?` | "unexpected character '?'" — **`?` had no token at all** | emitted as an operator; the suffix parser already expected one |
| 2.2d | `{[K]: V, name: T}` mixed table type | "expected '}' but found ':'" — branch assumed every prop had the first prop's shape | prop-by-prop table-type parse |
| 2.2e | `{[string]: number}` indexer type | "expected ':' but found ':'" (`expectPunc(":")` on an **OP** token) | `expectOp(":")` |
| 2.2f | `n //= 4`, `s ..= "b"` | "expected an expression but found '='" — both are 3-char ops and the lexer only had a 2-char table | matched before the 2-char table |

**Not a bug:** `f(a), g(b)` is rejected and *should* be — Luau has no comma
operator, so a bare expression statement cannot have two expressions. My first
"false positive" report for it was wrong; the corpus now asserts the real grammar.

### 2.4 The worst mistake of this session: I reported work that had been erased

This is the entry I would want to read if I were handed this document, so it goes
in the main chart, not a footnote.

**What happened.** For one stretch I ran every edit with `cd "ZeroScript
Demo/ZeroScript-Free-1.5.5"` (the canonical tree) but wrote the *test* changes to
`zeroscript-extension-v2/test-bridge.py`. Then I ran
`scripts/sync_copies.py --write`, which copies canonical → bundle for the whole
extension tree. That is correct behaviour for the tool, but it reverted the test
file I had just edited, and — because several of my earlier Python edits had been
made while my shell was in the bundle mirror — it also overwrote those.

**What that cost, precisely.** Three commits (`aaf446e`, `3064f1e`, and the
bridge portion of the sync) carried messages describing `bridge.py` changes
(parallel `studio_full_tree`, single-flight probe, POSIX port lookup, FIFO
agent-temp eviction) and `team_hub.py` changes (`leave()` keeping the team alive,
the `event_log` off-by-one) **that were not present in the tree**. `test-bridge.py`
reported 26 assertions in my transcript while the file on disk still had 18. The
suite was green because it was testing the old code.

**How I caught it.** Not by re-reading my own summary — by grepping the *source*
for the identifiers the commit messages named
(`_port_owner_posix`, `_PROBE_NEG_TTL`, `_TREE_WORKERS`, `as_completed`) and
getting `0`. A sha1 of `bridge.py` before and after the sync showed it was
byte-identical to the pre-change file.

**What I changed so it cannot silently happen again.**
1. Every claim below is now backed by a grep of a unique identifier *in the
   canonical file* plus a sha1 before/after the sync, recorded in the transcript.
2. `scripts/sync_copies.py --check` was run after every edit batch, and it now
   prints the count it verified (`59 verified`) so "clean" is a number.
3. The test file is the load-bearing artifact: `test-bridge.py` went 18 → 26
   assertions, and `npm run verify` prints the per-file assertion count, so a
   reverted test file shows up as a smaller number instead of passing silently.

**The general lesson, stated plainly:** a green suite only means the files it ran
were correct. It says nothing about whether the files you *think* you edited are
the ones on disk. Any workflow with a copy/sync step needs the source-side
identifier check, not just the test result.

### 3.1 I "upgraded" history and had to put it back

While bumping the release identity I ran one regex over every `4.6.0` in every
doc. That also rewrote statements that are *about the past*:

- `## What 4.6.0 fixed (Bridge Teams, …)` became "What **4.7.0** fixed"
- "Mostly it did **not** before 4.6.0" became "before **4.7.0**"
- "There were 392 empty `catch {}` blocks in 4.6.0" became "in **4.7.0**"
- `## … upgrades in 4.6.0` became "in **4.7.0**"
- "Enforced role boundaries in 4.6.0" became "in **4.7.0**"

All five were false: those changes shipped in 4.6.0 and did not ship in 4.7.0.
I caught them on re-read and reverted them. A find-and-replace that moves a
version number across prose cannot tell "we are now this version" from "this is
what that version did", and the second kind becomes a lie the moment it ships.

**The speed claim, stated honestly.** The only latency figure in this release
that was *measured* rather than *reasoned about* is `studio_full_tree`: against
a stubbed client at 50 ms per call, **1.35 s serial → 0.20 s concurrent** (peak
concurrency 8), asserted in `test-bridge.py` so it cannot silently regress. The
other performance work is complexity reduction whose benefit depends on
workload (O(n) → O(1) eviction; one probe per status burst instead of one per
tick; 3 tree round-trips instead of 27). I did not benchmark those against a
live Studio session, and this document does not invent a millisecond for them.

## 5. What I could not verify

Honesty section, because "0% lies" includes the things I did not do.

- **No real Roblox Studio run.** Studio is not available in this environment.
  Every Studio interaction is tested against stubs and against the protocol, not
  against the application. `studio_full_tree`'s real-world timing is therefore
  unmeasured; the 1.35 s → 0.20 s figure comes from a stub that sleeps.
- **No real browser.** The jsdom tests exercise the module graph and the DOM
  contracts, not Chrome's actual message-delivery timing or a live network.
- **The three biggest providers are not interactively tested.** The 18 provider
  files share a boot contract asserted by `test-two-tabs.js` and
  `simulate-load.js`; that is structural coverage, not proof that a given AI
  site's DOM selectors still match today's markup.
- **`bridge.py`'s WebSocket path** is exercised by `test-bridge.py` and
  `tests/test_bridge_team.py` over a real socket, but never with a real MCP
  client attached.
- **macOS-specific launcher behaviour** was syntax-checked (`bash -n`,
  `--check`) on Linux. The `lsof` port probe has not run on macOS.
